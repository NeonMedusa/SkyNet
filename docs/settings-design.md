# TUI 设置页设计（2026-10-13 定稿）

**一句话**：把散落在 `config.json` 与代码常量里的"行为开关"集中成一个 TUI 设置页；第一版聚焦**模型输出**与**压缩行为**。

**状态：已实现（2026-10-13）**。实现细节：入口 = `/settings` 命令或帮助菜单；交互 = ↑↓ 选择、←→/Enter 调整（**数字行用预设档位循环**，任意值可手改 config.json）、Esc 返回；改动即时持久化。

**本文的定位**：实现依据（照此落地）+ 决策存档（为什么是这些选项）。后续开发者请先读本文再动设置相关代码。

---

## 背景（为什么会有这一页）

- 直接动因：SawDust 会话的压缩事故系列（2026-10-13）——模型把"写摘要"变成"继续干活"，垃圾摘要曾两次落库；随后围绕"压缩行为"的开关需求集中爆发（垃圾审核、失败重试、剥离思考、思考档、止损……），而这些此前**大多只能改代码常量**。
- 现状：`config.json` 已有少量用户可配项（如 `max_output_tokens`、`ambiguous_width`），其余行为参数散在代码里（如 `auto_compact_pct` 默认 90、`keep_recent_tokens` 默认 20000、折叠启发式常量、垃圾审核常量）。
- 目标读者：用户 + 后续开发者。

## 设计原则（三条）

1. **默认值 = 现行为**：所有开关默认不改变现状（不改就是不变）；
   （例外：自动压缩阈值默认 85%、旧工具输出折叠默认关——用户定，2026-10-14）
2. **开关语义要能用一条原则讲清**（例：审核 = 输出质量的唯一总闸）；
3. **少隐式行为**：能显式配置的，不做隐式自动（例：不做"重试自动降思考"，用户发现压缩出问题会自己调）。

## 设置项总表（定稿）

### 【模型与输出】

| # | 选项 | 类型 | 默认 | 语义 |
|---|---|---|---|---|
| 1 | 输出上限 | 数字（UI 按 k 显示） | `0` | 0 = 不发送（跟随模型/网关默认）；设值后按模型能力表钳制（`min(用户值, max_out)`）；行内显示"实际生效值" |
| 2 | 回传思考 | 三态：自动 / 强制开 / 强制关 | 自动 | 自动 = 跟随能力表（`interleaved` 字段）；**强制关有 400 风险**（部分网关必须回传），行内给警示 |

### 【压缩】

| # | 选项 | 类型 | 默认 | 语义 |
|---|---|---|---|---|
| 3 | 自动压缩 | 开/关 | 开 | 关 = 不自动触发中途压缩（手动 `/compact` 仍可用） |
| 4 | 自动压缩阈值 | 百分比（70/80/85；钳制 50..85） | `85%` | 上下文估算到该占比触发中途压缩；上限 85（90 实战中已容易先炸，留余量），下限防频繁压缩（小窗口模型留余量） |
| 5 | 保留窗口 | 数字（tokens，**UI 按 k 显示**：0.5k/1k/2k/4k/8k/20k/50k/100k） | `20k` | "除最近几条消息以外"的"几条"；`/compact N` 可按次覆盖 |
| 5 | 压缩时思考档 | 循环：跟随会话 / off / low / medium / high / max | 跟随会话 | 指定后**首试与重试都用该档**；无任何隐式降档 |
| 6 | 摘要垃圾审核 | 开/关 | 开 | **开**：流式早停 + 落库前校验（标记/过短）+ **截断检查** → 坏则重试 → 仍坏则**止损（中断本回合 + 三选项通知）**；**关**：盲采——只要成功拿到输出就采用（含半截/垃圾，照常落库并截断上下文），行内给警示 |
| 7 | 压缩失败重试 | 开/关 | 开 | 仅"审核开"时有意义：坏输出重试一次（定向提示 + 按 #8 决定是否剥离思考）；关 = 首次坏即放弃 + 止损 |
| 8 | 压缩时剥离思考 | 三态：从不 / 总是 / 仅失败重试时 | 仅失败重试时 | 摘要载荷是否携带 `[thinking]` 文本段 |

### 【上下文】

| # | 选项 | 类型 | 默认 | 语义 |
|---|---|---|---|---|
| 9 | 旧工具输出折叠 | 开/关 | 关 | 开 = 旧输出折叠省上下文，但改历史 → 前缀缓存频繁失效；关 = 全文进请求（涨得快、缓存稳） |
| — | 恢复默认设置 | 操作 | — | 两关确认后设置页全部选项回默认（提供商/模型/会话不受影响），即时保存 |

### 统一约定

- **持久化到 `config.json`**；设置页每行显示当前值，回车循环/编辑；
- **手动 `/compact` 与自动压缩共享同一份设置**（尤其"审核"关掉时两边都不拦）；
- **技术底线（不属于任何开关，永不可关）**：
  - **空摘要**（模型零字节输出）永不落库——没有东西可存；
  - **请求层失败**（网络错误/超窗/掐流）走现有重试/退避流程，耗尽则跳过压缩、回合继续——**不触发止损**（止损只针对"成功拿到输出但输出是坏的"）。

## 各设置项：现状 → 目标 → 接线点

1. **输出上限**：现状 = `config.max_output_tokens`（已存在，默认 0）；目标 = 设置页可改；接线 = 已有（`resolveMaxOutputTokens`）。
2. **回传思考**：现状 = 能力表自动（`createStreamJob` 填 `behavior.interleaved`）；目标 = 三态覆盖层；接线 = 该填充处加"强制开/强制关"分支。强制关前确认用户知晓 400 风险。
3. **自动压缩**：现状 = `AppState.auto_compact_pct` 默认 90（非配置）；目标 = 配置开关（关 = pct 0）+ **阈值百分比**（`config.auto_compact_pct`，钳制 50..85，缺省 85）；接线 = `job.auto_compact_pct` 的来源（`createStreamJob`）+ 启动播种 + 设置页即时同步。
4. **保留窗口**：现状 = `AppState.keep_recent_tokens` 默认 20000，`/compact N` 会改写该状态；目标 = 进配置（作为默认值）；接线 = `createStreamJob` 拷入 job 处；UI 按 k 显示（0.5k 起，支持一位小数 k），任意值仍可手改 config.json。
5. **压缩时思考档**：现状 = 摘要请求继承会话档（`sessionThinkingEffort`）+ 坏输出重试**自动降档**（`retry_thinking_lower` 机制，2026-10-13 加、同日决定移除）；目标 = 单一设置项；接线 = 压缩请求 `reasoning_effort` 来源改为"设置档（follow 时取会话档）"，**并删除 `retry_thinking_lower` 整条机制**。
6. **摘要垃圾审核**：现状 = `context.summary_garbage_check_enabled` 常量（true；2026-10-13 曾置 false 做观察实验：证实"关掉后模型输出 14k 字符幻觉续写照常落库"，检查机制无假阳性）+ 截断检查（`last_stopped_by_length`）独立常开；目标 = 单一配置项，**截断检查并入**；接线 = ①`SummaryCollector` 流式早停条件；②两条压缩路径（`compactJobHistory` / `compactionExecute`）的校验条件；③把 `last_stopped_by_length` 检查移入该开关。
7. **压缩失败重试**：现状 = 坏输出必重试一次；目标 = 开关；接线 = 两条路径的 `garbage_retries` 分支入口。
8. **压缩时剥离思考**：现状 = 首试带、坏输出重试剥；目标 = 三态；接线 = `buildCompactionPayload` 的 `include_thinking` 参数来源。
9. **旧工具输出折叠**：**默认已改关（2026-10-14：折叠会改历史 → 前缀缓存命中频繁归零，收益/损失比待研究）**；原现状 = 常开（启发式：`fold_protect_turns=2`、`fold_min_output_bytes=1024`、`fold_min_bytes=80KB`、`fold_protect_bytes=160KB`）；目标 = 开关；接线 = 折叠执行点（worker/main 折叠调用处）。

10. **恢复默认设置**（设置页操作行）：两关确认弹窗（模式 `settings_reset_confirm`，复用 confirm_stage/confirm_yes）；`resetSettingsToDefaults` 从 Config 字段默认取值并即时保存。

## 决策记录（为什么是这样）

- **回传思考做三态而非二态**：部分网关必须回传（缺失会 400 "reasoning_content must be passed back"），粗放的"否"会直接打坏这类会话；"强制关"仅作调试/省 token 的逃生口。
- **"审核 = 输出质量的唯一总闸"**：截断检查（输出被上限掐断）归入审核——审核关 = 只要成功拿到输出就采用（含半截）；"部分盲采"方案被否（开关语义讲不清）。
- **失败止损归入审核**（不单列开关）：审核关 = 盲采，不应有止损。
- **压缩思考档替代"重试自动降思考"**：少一个隐式行为；用户发现压缩出问题会自己调档。
- **不做"压缩专用模型"**：审核失败的通知已提示"换模型后重试"，引导足够；需要时先切会话模型触发压缩。
- **折叠单开【上下文】组**：它影响的是全部请求而不只是压缩。
- **阈值钳制 50..85**：上限 85（实战中 90% 前请求就可能开始失败，留余量）；下限防频繁压缩（小窗口模型留余量）。

## 未纳入候选（存档，供将来斟酌）

| 候选 | 先不做的原因 |
|---|---|
| 压缩专用模型（跟随会话/指定） | 通知引导 + 手动切模型已够用；真要做再说 |
| 自动压缩阈值档 | 已实现（百分比档位入设置页，2026-10-13） |
| 无进度看门狗升级（"无进度就切"） | 先攒日志数据（已有"无进度"观察日志） |
| 折叠激进程度/阈值 | 先只做开/关；启发式常量暂不暴露；**收益/损失比与调优待研究**（折叠改历史 → 缓存命中频繁归零，2026-10-14 默认已改关） |
| 压缩提示词自定义 | 大工程；且提示词是压缩质量的最后防线，不宜随意改 |
| `/compact` 确认框开关 | 小细节，可选 |
| 摘要重试提示词开关/自定义 | 细节，不建议单列 |
| 压缩重试次数/退避参数 | 内部调参，不建议进设置页 |
| 缓存亲和（cache_key/retention）开关 | provider 级已有配置，不建议进设置页 |

## 实现规划（初稿）

1. **config.json 新字段**（全部缺省 = 现行为）：
   - `max_output_tokens`（已有；默认 0）
   - `interleaved_mode`: `auto` | `on` | `off`（默认 auto）
   - `auto_compact`: bool（默认 true；false → pct=0）
   - `auto_compact_pct`: 数字（默认 85；10..100 钳制）
   - `keep_recent_tokens`: 数字（默认 20000）
   - `compaction_thinking`: `follow` | `off` | `low` | `medium` | `high` | `max`（默认 follow）
   - `summary_garbage_check`: bool（默认 true）
   - `compaction_retry`: bool（默认 true）
   - `compaction_strip_thinking`: `never` | `always` | `retry_only`（默认 retry_only）
   - `fold_old_tool_outputs`: bool（默认 false，2026-10-14 起；此前 true）
2. **TUI 设置页**：三组列表；行 = 名称 + 当前值；回车循环/编辑；Esc 关闭；改后即时持久化。
3. **代码清理**：移除 `retry_thinking_lower` 机制；`summary_garbage_check_enabled` 常量退位为缺省值来源（或删除）。
4. **测试**：config 解析往返（新字段）；各开关接线单测（审核开/关的放行行为、剥离思考三态、重试开关、思考档覆盖、折叠开关）；mock 集成按现有惯例。
5. **落地顺序**：先 config 字段 + 接线（行为可测）→ 再设置页 UI。
